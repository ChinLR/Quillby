# Quillby: Wizard on Call - An AI Agent That Fights Customer-Service Bots For You

An AI agent that argues with a company's support bot on your behalf. It reads your documents and the company's published policy, wears the bot down until a human takes over, negotiates with that human, and then answers the phone call when the company says "let me ring you". You watch every move live and can step in at any time.

Built for the **Edinburgh AI Hackathon** (theme: take something we assume works one way and flip it). Today a human fights a company's bot. We flip it: your bot fights their bot, and then pries a human out, so it ends as **our bot against their human**.

> *Companies automated customer service to avoid talking to you. We automated you to make them talk.*

The product is called **Quillby** (the wizard mascot). In the code and docs the engine is called **Counterbot**; they are the same thing.

---

## Important: What Is Real and What Is Simulated

This is a hackathon demo, and the other side of the conversation is a simulation we built. Here is exactly what is what.

**Real**

- **The agent's decisions and wording**, generated by an LLM (Nebius Token Factory) and checked by guards.
- **Reading your files**: text, email, PDF, Word and images (images are read by a vision model).
- **Reading the company's policy**: the agent fetches the policy page over HTTP, finds the relevant clauses, and only keeps a quote if it appears word for word on the page.
- **The phone call**: a real call through Twilio, answered by an ElevenLabs voice agent that knows your case.
- **The live dashboard**: every message, tactic and offer is streamed to the screen as it happens.

**Simulated**

- **The airline and its chat bot ("Northwind Air" and "Nova")** are fictional. The bot is a scripted program with menus and handoff rules, not an AI, and not a real company.
- **The airline's policy page** is invented sample content (served at `/northwind/policy/`). The reading is real; the policy is not.
- **The human agent** is a teammate typing in an agent console, or a scripted agent (on by default).
- **The airline website** (`/northwind/`) is a read-only mirror of the conversation the backend is having. Nothing is typed into it. The typing animation is cosmetic.
- **The flight and booking** are fictional, and the delay is taken from your documents. No flight data is looked up.

**Replay mode.** For a reliable demo, every LLM answer is cached on disk and can be replayed with `REPLAY_MODE=1` (no model calls). The first run of any path is live.

## How It Works

1. **Tell us what happened.** Describe the problem and upload files (an email, a boarding pass, a receipt). The backend reads the files and an LLM extracts the facts: booking, flight, times, the airline's stated reason.
2. **Review.** The agent shows what it actually read, the airline's own policy clauses, and the UK law summary. You set what to ask for and the lowest you would accept.
3. **The fight.** The agent works through the airline's chat bot: it clicks the menu, states the claim, refuses the "did that help?" trap, quotes the law and the airline's own clause, and demands a human.
4. **The human.** When a person appears (detected from reply speed, wording and handoff phrases), the agent refuses vouchers, holds firm below your minimum, and negotiates.
5. **The call.** When the human says "let me call you", the agent gives its number. An ElevenLabs voice agent, loaded with your case, evidence and the policy quotes, answers the phone and negotiates live.
6. **The result.** The outcome, the transcript and the amount are shown, with a log of what happened.

## Planned Future Improvements

1. **Real chat adapters**: drive a real support chat in a browser (Playwright) instead of the simulated bot.
2. **Find policy pages automatically**: today only the demo airline has a mapped policy URL.
3. **Live call transcript**: ElevenLabs only provides the transcript after the call ends, so the dashboard shows the call lines at the end.
4. **More complaint types**: intake already classifies any complaint, but only flight delays are negotiated.
5. **Verify the delay**: check the claim against flight-status data.
6. **Persistent storage and a test suite**: state is in memory and testing is a smoke test.
7. **Multi-language support.**

## Tech Stack

### Backend

- **Python 3.11+** (developed on 3.12)
- **FastAPI** - API and server-sent events
- **Pydantic** - data models; the contract is generated as OpenAPI
- **OpenAI Python SDK** pointed at **Nebius Token Factory** (OpenAI-compatible API)
- **httpx** - policy fetching and the ElevenLabs API
- **pypdf** - PDF text extraction
- **asyncio** - the negotiation runs as a background task

### Frontend

- **React 19**, **TypeScript**, **Vite**
- **Tailwind CSS 4**
- **openapi-typescript** - API types are generated from the backend's `/openapi.json`, so a mismatch fails the build

### Services

- **Nebius Token Factory** - `DeepSeek-V4.1-Flash` for text, `Qwen3.8-27B` for images
- **ElevenLabs Conversational AI** - the voice agent (LLM, text-to-speech, speech recognition)
- **Twilio** - the phone number

## Features

### Core

- Reads uploaded files (text, email, PDF, Word, images) and extracts the facts with an LLM
- Reads the company's published policy and quotes it back word for word (quotes are verified against the page, never written by the LLM)
- Escalation ladder: orient, state the claim, refuse the loop, cite the rule, pressure, demand a human
- The engine decides which moves are allowed; the LLM picks one and writes the line; guards check every message
- Human detection from real signals: reply speed, canned phrases, handoff announcements, name introductions
- Negotiation rules in plain code: refuse vouchers, never go below the floor, counter once, accept at or above the floor
- A real phone call handled by an ElevenLabs voice agent, briefed with the case, evidence and policy
- Honesty rules: it says it is an AI assistant, never claims to be human, never invents evidence, never reveals your minimum

### Frontend

- Landing page, intake with file upload, review screen showing what was really read
- Live chat that reveals line by line, with a typing indicator
- Live tactic and duel view, call panel with timer and result, outcome report
- Pause and take over at any time
- An agent console for the person playing the human, with a cheat sheet and a scripted fallback agent
- The fictional airline site opens in its own tab and shows the support chat filling in

### Reliability

- Every LLM answer is cached; `REPLAY_MODE=1` replays them with no model calls
- If the LLM fails or times out, a template line is used and the run continues
- `ENGINE=stub` plays a fully scripted run with no LLM
- A manual "record result" button if the phone call can't be read

## Quick Start

### Prerequisites

- **Backend:** Python 3.11+
- **Frontend:** Node.js 20+ and npm
- **Required:** a Nebius Token Factory API key (the agent's reasoning)
- **Optional:** ElevenLabs account and a Twilio phone number (only for the live phone call)

### 1. Clone the repo

```bash
git clone https://github.com/ChinLR/EdinAIHack.git
cd EdinAIHack
```

### 2. Set up the backend

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cp .env.example .env
# Edit .env and add your Nebius key (see Configuration below)
```

### 3. Set up the frontend

```bash
cd frontend
npm install
cd ..
```

### 4. Run everything

```bash
./dev.sh
```

- App: `http://localhost:5173`
- Backend API docs: `http://localhost:8000/docs`
- The fictional airline site: `http://localhost:5173/northwind/`
- The airline's policy page: `http://localhost:5173/northwind/policy/`
- Agent console (for the person playing the human): `http://localhost:5173/#/agent`

### 5. Try it

Open the app, press **Start your claim**, and upload the three files in `demo-docs/` with the pre-filled description. Press **Take a look at my case**, then **Let Quillby fight for this**. The airline site opens in a new tab and the chat starts.

### 6. The live phone call (optional)

1. In ElevenLabs, create an agent. Turn on the **End call** tool.
2. Create an API key with **write** access to Agents (the backend sets the agent's prompt before each call).
3. Import your Twilio number under **Phone numbers** and assign the agent to it. (Twilio trial accounts only accept calls from verified numbers.)
4. Put `ELEVENLABS_API_KEY` and `ELEVENLABS_AGENT_ID` in `.env`.
5. Check it: `.venv/bin/python backend/voice_check.py`
6. When the chat says "let me give you a call", dial the number shown and play the airline.

Without these, the dashboard waits for the call and offers a **Record result** button instead.

### 7. Replay mode and the scripted fallback

```bash
# Serve only recorded LLM answers, no model calls
cd backend && REPLAY_MODE=1 ../.venv/bin/uvicorn main:app --port 8000

# A fully scripted run with no LLM at all
cd backend && ENGINE=stub ../.venv/bin/uvicorn main:app --port 8000
```

## Configuration

Settings live in `.env` (see `.env.example`).

| Variable | Required | Description |
| --- | --- | --- |
| `LLM_BASE_URL` | yes | Nebius Token Factory URL (OpenAI-compatible) |
| `LLM_API_KEY` | yes | Your Nebius key |
| `LLM_MODEL` | yes | Text model, e.g. `deepseek-ai/DeepSeek-V4.1-Flash` |
| `VISION_MODEL` | no | Image reader, default `Qwen/Qwen3.8-27B` |
| `ELEVENLABS_API_KEY` | for calls | Needs write access to Agents |
| `ELEVENLABS_AGENT_ID` | for calls | The voice agent |
| `COUNTERBOT_PHONE_NUMBER` | no | The number to show; otherwise looked up from ElevenLabs |
| `REPLAY_MODE` | no | `1` = serve only cached LLM answers |
| `ENGINE` | no | `stub` = scripted run with no LLM |
| `POLICY_BASE_URL` | no | Where the demo airline's policy is fetched from; defaults to this server's own port |
| `PUBLIC_MODE` | no | `1` = rate limits for a public link |
| `CALL_FEATURE` | no | `0` = no phone call; the agent settles in the chat |

## API Endpoints

All under `/api`. The full contract is in `.plans/contract.md`, and the generated OpenAPI is at `/openapi.json`.

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/health` | Health check, and whether replay mode is on |
| `GET` | `/case` | The current case |
| `POST` | `/intake` | Your description and files in; a case, evidence and policy clauses out |
| `POST` | `/negotiations` | Start the agent |
| `GET` | `/negotiations/{id}` | Current state |
| `GET` | `/negotiations/{id}/events` | Live events (server-sent events) |
| `GET` | `/negotiations/{id}/history` | The same events as JSON (polling fallback) |
| `POST` | `/negotiations/{id}/pause` | Pause (and `/resume`) |
| `POST` | `/negotiations/{id}/message` | Step in with your own message while paused |
| `GET` | `/negotiations/{id}/call` | Phone call state |
| `POST` | `/negotiations/{id}/call/outcome` | Record the call result by hand |
| `GET` | `/negotiations/{id}/report` | The final report |
| `POST` | `/reset` | Reset the demo |
| `GET` | `/company/inbox` | The agent console's view of the chat |
| `POST` | `/company/reply` | The human agent's reply |
| `POST` | `/company/auto-agent` | Turn the scripted agent on or off |

Static pages served by the backend: `/northwind/` (the airline site) and `/northwind/policy/`.

## Testing

There is no unit test suite yet. The demo path is covered by a smoke test and a setup check:

```bash
# Starts nothing itself: run ./dev.sh first, then
./smoke.sh
# Walks the whole demo path: intake, chat, handoff, call request, result. Prints SMOKE OK.

# Checks the ElevenLabs agent and Twilio number
.venv/bin/python backend/voice_check.py
```

The generated API types are checked by the frontend build: renaming a backend field makes `npm run build` fail.
